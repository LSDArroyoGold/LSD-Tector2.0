# PENDIENTE — monitoreo de batería por INA219 (voltaje/corriente vía I2C).
#
# HARDWARE: instalado y verificado funcionando el 3/9/2026. INA219 en
# serie en el cable positivo principal (entre pack y entrada del step-down
# -- así mide corriente real del sistema, no solo voltaje), VCC del propio
# módulo alimentado del 3.3V de la Pi (pin 1 -- no necesita estar siempre
# encendido, solo se lee mientras la Pi está despierta), SDA/SCL
# compartiendo el mismo bus I2C que el DS3231 (bus 1, dirección 0x40,
# sin conflicto con el 0x68 del RTC). Lecturas reales confirmadas:
# 7.596V / 478mA con la Pi corriendo birdnet-lsd normalmente -- ambos
# valores con sentido físico (2S2P Samsung INR18650-35E, ~3.8V/celda).
#
# SOFTWARE: todavía no está escrito. VENTANA_ACTIVA/CIERRE_FORZADO de acá
# abajo son plantilla heredada de la v1.1, nunca se cablearon a
# inicio_*.sh/cierre_*.sh en este repo -- hay que construir el watchdog
# reactivo de cero (cron cada 5 min leyendo el INA219, comparando contra
# UMBRAL_BATERIA_V, marcando CIERRE_FORZADO=TRUE), no alcanza con
# descomentar algo existente.
#
# DISEÑO ACORDADO (3/9, sesión con Diego) -- dos partes separadas a
# propósito, no una sola cosa:
#
# 1) CORTE DE SEGURIDAD (lo único que bloquea/cierra ventana): se queda
#    simple, umbral de voltaje puro, sin depender de ninguna curva ni
#    calibración -- cuanta menos lógica tenga la parte de seguridad,
#    mejor. Umbral ya definido:
#
#      UMBRAL_BATERIA_V=6.9   # ~3.45V/celda, ~15% de capacidad restante
#
#    Motivo del valor: deja ~0.4V/celda de margen sobre el peor caso
#    posible de disparo del BMS (3.05V/celda), cubre la caída IR del
#    propio BMS (<300mOhm) más el intervalo de 5 min entre chequeos del
#    watchdog, y evita ciclar las celdas cerca de su corte de fábrica
#    (2.65V/celda). Detalle completo: cuaderno de laboratorio, 14/8.
#
# 2) PORCENTAJE ESTIMADO (para logs/dashboard, NO gatilla nada): la
#    tensión bajo carga no es la tensión a circuito abierto (OCV) --
#    compensar con la corriente medida en la misma lectura:
#      V_ocv_estimado ≈ V_medido + I_medido × R_interna_del_pack
#    y despues mapear ese V_ocv a % con una curva. Arrancar con la curva
#    del datasheet Samsung INR18650-35E (nominal 3.60V, carga 4.2V, corte
#    fábrica 2.65V, 3350-3500mAh a 0.2C) como aproximación inicial -- pero
#    esa curva es de UNA celda a 0.2C (680mA) en laboratorio, no del pack
#    2S2P real con BMS y carga variable de este sistema, así que en algún
#    momento reemplazarla por una curva empírica propia:
#
#    PENDIENTE -- corrida de calibración (pedida por Diego, no hecha
#    todavía, dejar para cuando la pida explícitamente):
#      - Cargar el pack a 100% antes de arrancar (ahora estaba a 7.596V,
#        parcial -- para cubrir el tramo alto de la curva hace falta
#        arrancar de lleno).
#      - Desactivar temporalmente los 4 cron de ciclo de ventana
#        (inicio_amanecer/atardecer.sh, cierre_amanecer/atardecer.sh) para
#        que no corten la prueba a mitad de camino -- restaurar el
#        crontab automáticamente al terminar (o si falla algo, con trap).
#      - Dejar la Pi despierta corriendo birdnet-lsd de forma continua
#        (carga real, no artificial de banco) y loguear cada 60s:
#        timestamp, voltaje, corriente, mAh acumulados (coulomb counting
#        UNA sola vez, offline, para construir la tabla -- no en campo).
#      - Frenar en ~6.6V (margen sobre el corte del BMS en 6.1V), no
#        llevarlo hasta el fondo.
#      - Duración estimada: ~12-14hs, al consumo real medido (~470mA
#        promedio) sobre los ~7000mAh nominales del pack 2S2P.
#
# Cuando el INA219 esté instalado, activar algo del estilo (a definir
# junto con la lógica del watchdog en chequeo_bateria.sh):
#
